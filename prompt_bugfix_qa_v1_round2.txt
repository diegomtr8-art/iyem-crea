IMPORTANTE — OPCACHE
─────────────────────
El servidor tiene OPcache con validate_timestamps=0. Después de cada cambio PHP
debes limpiar OPcache. El método más confiable es vía XAMPP Control Panel:
Stop Apache → Start Apache. Si tienes acceso a terminal usa:
  php artisan opcache:clear
o accede a http://localhost/phpmyadmin/ → SQL y ejecuta selects de prueba.

ARCHIVO: app/Models/User.php, routes/web.php
PROBLEMA: Usuarios recién registrados acceden al portal sin verificar su email.
SOLUCIÓN:
  1. En User.php añadir:
       class User extends Authenticatable implements MustVerifyEmail {
  2. En routes/web.php el grupo portal ya tiene 'verified':
       Route::middleware(['auth', 'verified', 'ciudadano'])
     Verificar que sea así (ya estaba en el archivo — solo activar en User.php).
  3. Ejecutar: php artisan config:clear && php artisan cache:clear
  4. Con Gmail SMTP ya configurado, el correo de verificación ya se enviará.
VERIFICAR: Registrar nuevo usuario → debe llegar correo → sin verificar no entra.

[M-01] Relación CURP ↔ RFC no validada
ARCHIVOS: resources/js/Pages/Portal/WizardCredito.vue (paso 3 o donde esté RFC)
          app/Http/Controllers/Portal/WizardSolicitudController.php
PROBLEMA: El sistema acepta un CURP y un RFC de personas distintas.
SOLUCIÓN — FRONTEND (Vue, en tiempo real, no bloqueante):
  // Computed o watch en el paso donde aparezcan ambos campos:
  const rfcCurpWarning = computed(() => {
    if (form.rfc.length >= 4 && form.curp.length >= 4) {
      return form.rfc.slice(0, 4).toUpperCase() !== form.curp.slice(0, 4).toUpperCase();
    }
    return false;
  });
  // En el template, debajo del campo RFC:
  <p v-if="rfcCurpWarning" class="text-amber-600 text-xs mt-1">
    ⚠️ El RFC no parece corresponder al CURP ingresado. Verifica los datos.
  </p>
SOLUCIÓN — BACKEND (advertencia en log, no error bloqueante):
  En WizardSolicitudController.php, antes de guardar paso 3:
  if (strlen($rfc) >= 4 && strlen($curp) >= 4) {
      if (strtoupper(substr($rfc,0,4)) !== strtoupper(substr($curp,0,4))) {
          \Log::warning("CURP/RFC mismatch: solicitud={$solicitud->id} RFC={$rfc} CURP={$curp}");
      }
  }
VERIFICAR: Ingresar CURP de una persona, RFC de otra → aparece warning en UI.

[M-09] Proyección IE — fecha fin no se calcula automáticamente
ARCHIVO: WizardCredito.vue (paso de ingresos y egresos / proyección)
PROBLEMA: El usuario llena fecha inicio y fin manualmente — propenso a errores.
SOLUCIÓN:

    if (val) {
      const fin = new Date(val + 'T00:00:00');
      fin.setMonth(fin.getMonth() + 6);
      form.proyeccion_fecha_fin = fin.toISOString().split('T')[0];
    }
  });
  // El campo de fecha fin queda editable pero con el valor propuesto
VERIFICAR: Seleccionar fecha inicio → fecha fin se auto-llena con +6 meses.
