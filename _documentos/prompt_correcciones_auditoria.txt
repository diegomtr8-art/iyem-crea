## P0-1 — FLUJO INCORRECTO: ZIP SE GENERA AL ENVIAR, NO AL APROBAR
## ═══════════════════════════════════════════════════════

**Problema:** Actualmente en `WizardSolicitudController@generarFormatos` el ZIP con los
PDFs se genera cuando el ciudadano lo solicita antes de la aprobación. Esto es incorrecto:
el ciudadano puede descargar formatos con datos que aún no han sido validados.

**Solución — flujo correcto:**

1. Al enviar la solicitud → estatus = `Enviada`, mensaje: "Tu solicitud fue enviada.
   El equipo CREA revisará tu información." SIN ZIP, sin botón de descarga.

2. Solo cuando el operativo cambia estatus a `Aprobada` → disparar automáticamente
   la generación del ZIP en background y notificar al ciudadano.

3. El ciudadano solo ve el botón de descarga del ZIP cuando estatus = `Aprobada` y
   `formatos_zip_ruta` no es null.

**Implementación:**

a) Crear un Observer para `SolicitudCredito`:
   ```
   php artisan make:observer SolicitudCreditoObserver --model=SolicitudCredito
   ```
   En el método `updating()`, detectar cuando `estatus` cambia a `Aprobada`:
   ```php
   public function updating(SolicitudCredito $solicitud): void
   {
       if ($solicitud->isDirty('estatus') && $solicitud->estatus === 'Aprobada') {
           // Disparar job en background para no bloquear la request
           GenerarFormatosSolicitudJob::dispatch($solicitud->id);
       }
   }
   ```

b) Crear job `app/Jobs/GenerarFormatosSolicitudJob.php`:
   ```php
   public function handle(FormatosService $service): void
   {
       $solicitud = SolicitudCredito::with(['modalidad', 'aval'])->findOrFail($this->solicitudId);
       $ruta = $service->generarZip($solicitud);
       $solicitud->update(['formatos_zip_ruta' => $ruta]);
       // Enviar notificación al ciudadano (ver P1-1)
   }
   ```

c) Registrar el observer en `AppServiceProvider::boot()`:
   ```php
   SolicitudCredito::observe(SolicitudCreditoObserver::class);
   ```

d) En `WizardSolicitudController`:
   - Eliminar la ruta `POST /solicitud/generar-formatos` o protegerla para que solo
     sea invocable si estatus = `Aprobada` (como fallback manual para operativos).
   - La ruta `GET /solicitud/{id}/descargar-formatos` debe verificar que
     `$solicitud->formatos_zip_ruta !== null` y que el usuario es dueño.

e) En el frontend `portal/WizardCredito.vue` y `portal/Dashboard.vue`:
   - Si estatus = `Enviada` o `En_Revision` → mostrar banner: "Tu solicitud está siendo
     revisada. Te avisaremos cuando haya novedades."
   - Si estatus = `Aprobada` y zip disponible → mostrar botón "Descargar formatos (ZIP)"
     con mensaje: "¡Felicidades! Tu crédito fue aprobado. Descarga los formatos, fírmalos
     y entrégalos en las oficinas CREA — Instituto Yucateco de Emprendedores,
     Calle 60 No. 395 por 45 y 47, Col. Centro, Mérida, Yucatán."

## P0-2 — DOCUMENTOS SUBIDOS EN DISCO PUBLIC (ACCESO SIN AUTENTICACIÓN)
## ═══════════════════════════════════════════════════════

**Problema:** Verificar y garantizar que todos los archivos que suben los ciudadanos
(INE, CURP, comprobantes, etc.) se almacenan en disco `local` (privado), nunca en
disco `public`. Los documentos contienen datos personales sensibles (CURP, domicilio,
fotografías).

**Revisa:** `WizardSolicitudController@subirDocumento` y `SolicitudCreditoController`.

**Solución:**

a) En `WizardSolicitudController@subirDocumento`, asegúrate de que el almacenamiento usa:
   ```php
   $ruta = $request->file('archivo')->store(
       "solicitudes/{$solicitud->id}/documentos",
       'local'  // ← disco local, NO 'public'
   );
   ```

b) Si encuentras algún archivo guardado con `Storage::disk('public')` o
   `->store('...', 'public')` en cualquier parte del código relacionado con documentos
   de solicitudes ciudadanas, corrígelo a `'local'`.

c) La ruta de descarga autenticada ya existe:
   `GET /mi-portal/documentos/{documento}/descargar` → `WizardSolicitudController@descargarDocumento`
   Verifica que esta ruta comprueba que `$documento->solicitud->user_id === auth()->id()`
   antes de servir el archivo. Si no lo hace, agrégalo.

d) Para el panel operativo, verifica que la descarga de documentos de una solicitud también
   pase por una ruta autenticada con middleware `operativo`. Si los documentos se sirven
   con `url` pública, corrígelo para que usen Storage::disk('local')->temporaryUrl() o
   una ruta de descarga protegida equivalente.

e) Migración de archivos existentes: si hay archivos en storage/app/public/solicitudes/,
   muévelos a storage/app/solicitudes/ con un comando artisan:
   ```php
   php artisan tinker
   // Storage::disk('local')->allFiles('solicitudes/') para verificar
   ```

## P0-4 — VALIDACIÓN DE MONTO DESCONECTADA DE LA MODALIDAD EN EL WIZARD
## ═══════════════════════════════════════════════════════

**Problema:** En el wizard ciudadano, cuando el usuario escribe el monto a solicitar, la
validación de mínimo/máximo no se actualiza dinámicamente según la modalidad seleccionada.

**Solución:**

a) En `WizardSolicitudController@guardarPaso`, cuando el paso incluye `monto_solicitado`,
   validar contra la modalidad ya seleccionada:
   ```php
   if (isset($data['monto_solicitado'])) {
       $modalidad = ModalidadCrea::find($solicitud->modalidad_id ?? $data['modalidad_id']);
       if ($modalidad) {
           $request->validate([
               'monto_solicitado' => [
                   'numeric',
                   "min:{$modalidad->monto_minimo}",
                   "max:{$modalidad->monto_maximo}",

               'monto_solicitado.min' => "El monto mínimo para {$modalidad->nombre} es $" . number_format($modalidad->monto_minimo, 0) . ".",
               'monto_solicitado.max' => "El monto máximo para {$modalidad->nombre} es $" . number_format($modalidad->monto_maximo, 0) . ".",
   ```

## P1-1 — NOTIFICACIONES: MIGRAR A LARAVEL DATABASENOTIFICATION
## ═══════════════════════════════════════════════════════

**Problema actual:** El sistema usa el modelo `AnuncioCiudadano` para enviar mensajes del
operativo al ciudadano. Esto es un sistema casero que no tiene badge de "no leídas" en
tiempo real, ni dropdown estándar, ni integración con el sistema de notificaciones de
Laravel.

**Solución:** Implementar Laravel `DatabaseNotification` para eventos del sistema,
manteniendo `AnuncioCiudadano` solo para mensajes manuales del operativo.

a) Crear las notificaciones en `app/Notifications/`:

```php
// SolicitudEnviadaNotification.php
class SolicitudEnviadaNotification extends Notification
{
    public function via($notifiable): array { return ['database']; }
    public function toDatabase($notifiable): array {
        return [
            'titulo'  => 'Solicitud recibida',
            'mensaje' => 'Tu solicitud fue enviada correctamente. El equipo CREA la revisará pronto.',
            'tipo'    => 'info',
            'url'     => route('portal.dashboard'),
        ];
    }
}

// SolicitudAprobadaNotification.php — incluir URL de descarga del ZIP
// SolicitudRechazadaNotification.php — incluir motivo
// DocumentacionIncompletaNotification.php — incluir qué documentos faltan
// En_RevisionNotification.php
```

b) Disparar las notificaciones en `SolicitudOperativoController@cambiarEstatus`:
   ```php
   match ($nuevoEstatus) {
       'En_Revision'             => $solicitud->user->notify(new En_RevisionNotification($solicitud)),
       'Aprobada'                => $solicitud->user->notify(new SolicitudAprobadaNotification($solicitud)),
       'Rechazada'               => $solicitud->user->notify(new SolicitudRechazadaNotification($solicitud)),
       'Documentacion_Incompleta'=> $solicitud->user->notify(new DocumentacionIncompletaNotification($solicitud)),
       default => null,
   };
   ```
   También disparar `SolicitudEnviadaNotification` en `WizardSolicitudController` cuando
   el ciudadano envía la solicitud.

c) En el Observer del job de ZIP (P0-1), al terminar de generar:
   ```php
   $solicitud->user->notify(new FormatosListosNotification($solicitud));
   ```

d) Agregar ruta en el portal:
   ```php
   Route::get('notificaciones', [BeneficiarioController::class, 'notificaciones'])->name('notificaciones.lista');
   Route::post('notificaciones/{id}/leer', [BeneficiarioController::class, 'marcarLeida'])->name('notificaciones.leer');
   Route::post('notificaciones/leer-todas', [BeneficiarioController::class, 'marcarTodasLeidas'])->name('notificaciones.leer-todas');
   ```

e) En `BeneficiarioController@index`, pasar al frontend:
   ```php
   'notificaciones' => auth()->user()->notifications()->latest()->take(10)->get()->map(fn($n) => [
       'id'      => $n->id,
       'leida'   => !is_null($n->read_at),
       'titulo'  => $n->data['titulo'],
       'mensaje' => $n->data['mensaje'],
       'tipo'    => $n->data['tipo'],
       'url'     => $n->data['url'] ?? null,
       'fecha'   => $n->created_at->diffForHumans(),
   ]),
   'no_leidas' => auth()->user()->unreadNotifications()->count(),
   ```

f) En el Navbar del portal ciudadano, el ícono de campanita debe:
   - Mostrar badge rojo con el número de `no_leidas` cuando > 0
   - Al hacer clic, abrir dropdown con las últimas 10 notificaciones
   - Botón "Marcar todas como leídas"
   - Cada notificación lleva a su `url` y se marca como leída

g) Ejecutar migración si no existe:
   ```bash
   php artisan notifications:table
   php artisan migrate
   ```

## P1-2 — TABLA EDITABLE DE DESTINO DEL CRÉDITO (CONCEPTOS LIBRES)
## ═══════════════════════════════════════════════════════

**Problema:** En el paso "Destino del Crédito" del wizard, el usuario no puede escribir
los conceptos (qué va a comprar y cuánto cuesta). Es fundamental para los formatos IYEM.

**Solución — en `portal/WizardCredito.vue`, en el paso de destino del crédito:**

a) Agregar un campo `conceptos_destino` en `datos_wizard` (array de objetos):
   ```json
   [
     { "concepto": "Máquina de coser industrial", "importe": 15000 },
     { "concepto": "Materia prima (tela)", "importe": 5000 }
   ]
   ```

b) Componente Vue de tabla editable:
   ```vue
   <template>
     <div>
       <table class="w-full text-sm">
         <thead>
           <tr>
             <th class="text-left">Concepto / Descripción</th>
             <th class="text-right w-40">Importe ($)</th>
             <th class="w-10"></th>
           </tr>
         </thead>
         <tbody>
           <tr v-for="(item, i) in conceptos" :key="i">
             <td><input v-model="item.concepto" type="text" placeholder="Ej. Máquina industrial" class="w-full border rounded px-2 py-1" /></td>
             <td>
               <input v-model.number="item.importe" type="text"
                 @input="formatearMiles($event, item)"
                 class="w-full text-right border rounded px-2 py-1" />
             </td>
             <td><button @click="eliminarFila(i)" class="text-red-500">✕</button></td>
           </tr>
         </tbody>
       </table>
       <button @click="agregarFila" class="mt-2 text-sm text-blue-500">+ Agregar concepto</button>
       <div class="mt-3 text-right font-bold">
         Total: {{ formatMoney(totalConceptos) }}
       </div>
       <p v-if="totalConceptos !== montoSolicitado" class="text-red-500 text-xs mt-1">
         El total de conceptos (${{ formatMoney(totalConceptos) }}) debe ser igual al monto solicitado (${{ formatMoney(montoSolicitado) }}).
       </p>
     </div>
   </template>

   <script setup>
   const totalConceptos = computed(() => conceptos.value.reduce((s, c) => s + (c.importe || 0), 0));

   function formatearMiles(event, item) {
     const raw = event.target.value.replace(/[^0-9]/g, '');
     item.importe = parseInt(raw) || 0;
     event.target.value = raw ? parseInt(raw).toLocaleString('es-MX') : '';
   }
   </script>
   ```

c) Validación al avanzar: `totalConceptos === montoSolicitado`. Si no, mostrar error
   y no permitir continuar al siguiente paso.

d) En `WizardSolicitudController@guardarPaso`, al recibir el paso de destino:
   ```php
   $data['conceptos_destino'] = collect($request->conceptos_destino)->map(fn($c) => [
       'concepto' => strip_tags($c['concepto'] ?? ''),
       'importe'  => (float) ($c['importe'] ?? 0),
   ])->filter(fn($c) => $c['concepto'] && $c['importe'] > 0)->values()->toArray();

   $totalConceptos = collect($data['conceptos_destino'])->sum('importe');
   if (abs($totalConceptos - $solicitud->monto_solicitado) > 1) {
       return response()->json(['error' => 'El total de conceptos debe ser igual al monto solicitado.'], 422);
   }
   ```

## P1-4 — PRÓXIMA CUOTA CARD EN "MI CRÉDITO" DEL PORTAL
## ═══════════════════════════════════════════════════════

**Problema:** La vista `portal/MiCredito.vue` muestra la tabla de amortización completa
pero no destaca de forma prominente la próxima cuota a pagar, su fecha de vencimiento
y si hay mora acumulada.

**Solución:**

a) En `MiCreditoController@index`, calcular y enviar `proxima_cuota`:
   ```php
   $hoy = now()->toDateString();
   $proxima = $credito->amortizaciones()
       ->whereNotIn('estado', ['Pagado', 'Condonado', 'Reestructurada'])
       ->orderBy('fecha_vencimiento')
       ->first();

   $diasMora = 0;
   $mora = 0.0;
   if ($proxima && $proxima->fecha_vencimiento < $hoy) {
       $diasMora = now()->diffInDays($proxima->fecha_vencimiento);
       if ($diasMora > 5) {
           $tasaDiaria = ($credito->tasa_interes_moratorio / 100) / 360;
           $mora = round((float)$proxima->saldo_insoluto * $tasaDiaria * $diasMora, 2);
       }
   }

   // En el array de respuesta del credito:
   'proxima_cuota' => $proxima ? [
       'numero'            => $proxima->numero_cuota,
       'fecha_vencimiento' => $proxima->fecha_vencimiento,
       'capital'           => (float) $proxima->capital_esperado - (float) $proxima->capital_pagado,
       'interes'           => (float) $proxima->interes_ordinario_esperado - (float) $proxima->interes_ordinario_pagado,
       'mora'              => $mora,
       'total'             => round(((float)$proxima->capital_esperado - (float)$proxima->capital_pagado)
                                  + ((float)$proxima->interes_ordinario_esperado - (float)$proxima->interes_ordinario_pagado)
                                  + $mora, 2),
       'dias_mora'         => $diasMora,
       'vencida'           => $proxima->fecha_vencimiento < $hoy,
   ] : null,
   ```

b) En `portal/MiCredito.vue`, mostrar al inicio de la página una card prominente:

```vue
<div v-if="credito.proxima_cuota" :class="[
  'rounded-xl p-5 mb-6 border-l-4',
  credito.proxima_cuota.vencida
    ? 'bg-red-50 border-red-500 dark:bg-red-950'
    : 'bg-green-50 border-green-500 dark:bg-green-950'
]">
  <h3 class="font-bold text-lg mb-3">
    {{ credito.proxima_cuota.vencida ? '🔴 Cuota vencida' : '📅 Próxima cuota' }}
  </h3>
  <div class="grid grid-cols-2 md:grid-cols-4 gap-4">
    <div><p class="text-xs text-gray-500">Vencimiento</p>
         <p class="font-bold">{{ formatDate(credito.proxima_cuota.fecha_vencimiento) }}</p></div>
    <div><p class="text-xs text-gray-500">Capital</p>
         <p class="font-bold">{{ formatMoney(credito.proxima_cuota.capital) }}</p></div>
    <div><p class="text-xs text-gray-500">Interés</p>
         <p class="font-bold">{{ formatMoney(credito.proxima_cuota.interes) }}</p></div>
    <div v-if="credito.proxima_cuota.mora > 0">
         <p class="text-xs text-red-500">Mora acumulada</p>
         <p class="font-bold text-red-600">{{ formatMoney(credito.proxima_cuota.mora) }}</p></div>
  </div>
  <div class="mt-4 pt-3 border-t flex justify-between items-center">
    <span class="text-xs text-gray-500">
      {{ credito.proxima_cuota.dias_mora > 0 ? credito.proxima_cuota.dias_mora + ' días de atraso' : '' }}
    </span>
    <span class="text-xl font-extrabold">
      Total a pagar: {{ formatMoney(credito.proxima_cuota.total) }}

  </div>
```

## P1-6 — ALERTA DE PRESUPUESTO AGOTADO AL REGISTRAR CRÉDITO
## ═══════════════════════════════════════════════════════

**Problema:** Un operativo puede registrar créditos aunque el presupuesto de la modalidad
esté agotado. No hay ninguna alerta ni bloqueo.

**Solución:**

a) En `SolicitudOperativoController@registrarCredito` (vista) y `@guardarCredito` (store),
   verificar el presupuesto antes de mostrar el formulario y antes de guardar:

```php
private function verificarPresupuesto(int $modalidadId, float $monto): array
{
    $anio = now()->year;
    $presupuesto = PresupuestoPrograma::where('modalidad_id', $modalidadId)
        ->where('ejercicio_fiscal', $anio)
        ->first();

    if (!$presupuesto) {
        return ['alerta' => true, 'mensaje' => 'No hay presupuesto registrado para esta modalidad en ' . $anio . '.'];
    }

    $ejercido = Credito::where('modalidad_id', $modalidadId)
        ->where('estatus', '!=', 'Cancelado')
        ->whereYear('fecha_entrega', $anio)
        ->sum('monto_otorgado');

    $disponible = (float)$presupuesto->monto_autorizado - (float)$ejercido;

    if ($monto > $disponible) {
        return [
            'bloqueado' => true,
            'mensaje'   => "El monto solicitado ($" . number_format($monto, 2) . ") supera el presupuesto disponible ($" . number_format($disponible, 2) . ") para esta modalidad.",
        ];
    }

    if ($disponible < ($presupuesto->monto_autorizado * 0.1)) {
        return [
            'alerta'  => true,
            'mensaje' => "⚠️ Presupuesto casi agotado. Disponible: $" . number_format($disponible, 2) . ".",
        ];
    }

    return ['ok' => true, 'disponible' => $disponible];
}
```

b) En `@registrarCredito` (GET), pasar la alerta al Inertia:
   ```php
   'presupuesto_status' => $this->verificarPresupuesto($solicitud->modalidad_id, $solicitud->monto_solicitado),
   ```

c) En la vista de registro de crédito, mostrar el alerta visualmente. Si está bloqueado,
   deshabilitar el botón de guardar.

## P1-7 — ALERTAS AUTOMÁTICAS DE CUOTAS PRÓXIMAS (SCHEDULER)
## ═══════════════════════════════════════════════════════

**Problema:** El endpoint `GET /api/notificaciones/cuotas` existe pero no está en el
scheduler de Laravel. Los acreditados no reciben aviso antes de que venza su cuota.

**Solución:**

a) Crear job `app/Jobs/NotificarCuotasProximasJob.php`:
```php
public function handle(): void
{
    $manana = now()->addDay()->toDateString();

    $cuotasManana = Amortizacion::whereDate('fecha_vencimiento', $manana)
        ->whereNotIn('estado', ['Pagado', 'Condonado', 'Reestructurada'])
        ->with(['credito.acreditado'])
        ->get();

    foreach ($cuotasManana as $cuota) {
        $credito = $cuota->credito;
        // Notificar al ciudadano vía DatabaseNotification
        $user = User::where('email', $credito->acreditado->correo)->first();
        if ($user) {
            $user->notify(new CuotaProximaNotification($credito, $cuota));
        }
    }
}
```

b) Crear `app/Notifications/CuotaProximaNotification.php`:
```php
public function toDatabase($notifiable): array
{
    return [
        'titulo'  => 'Tu cuota vence mañana',
        'mensaje' => "Tu cuota #" . $this->cuota->numero_cuota . " del crédito " . $this->credito->clave_contrato
                   . " vence mañana. Total a pagar: $" . number_format($this->cuota->pago_restante, 2),
        'tipo'    => 'warning',
        'url'     => route('portal.credito'),
    ];
}
```

c) En `app/Console/Kernel.php` (o usando `routes/console.php` en Laravel 11):
```php
// En routes/console.php
use App\Jobs\NotificarCuotasProximasJob;

Schedule::job(new NotificarCuotasProximasJob)->dailyAt('08:00')->timezone('America/Merida');
```
