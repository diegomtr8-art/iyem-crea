## CRÍTICO 1 — Subida de archivos no funciona (BLOCKER)
═══════════════════════════════════════════════════════════════════

Al hacer clic en "Subir" en la sección de documentos del wizard, aparece animación de
carga pero regresa al estado inicial. Ningún archivo se guarda. Bloquea el envío.

Diagnosticar y corregir en este orden:

1. Revisar `storage/logs/laravel.log` para el error exacto del endpoint de subida.

2. En `app/Http/Controllers/Portal/DocumentoSolicitudController.php` (o donde se maneje
   la subida), verificar que:
   - El método `store()` tiene `$request->validate(['archivo' => 'required|file|max:10240'])`
   - Se usa `$request->file('archivo')->store('documentos', 'local')` correctamente
   - La respuesta JSON es `{ ok: true, documento: { id, tipo, url, nombre } }`

3. Verificar permisos del filesystem:
   ```bash
   php artisan storage:link
   chmod -R 775 storage/app/documentos
   ```

4. En `config/filesystems.php` confirmar que el disk `local` apunta a `storage/app`.

5. En el Vue (WizardCredito.vue o el componente de documentos), verificar que el `fetch`/`axios`
   de subida envía correctamente:
   ```typescript
   const fd = new FormData();
   fd.append('archivo', file);
   fd.append('tipo_documento', tipo);
   fd.append('solicitud_id', solicitudId);
   // Header CSRF:
   axios.post(route('portal.documentos.subir'), fd, {
     headers: { 'Content-Type': 'multipart/form-data' }
   })
   ```

6. Verificar en `routes/web.php` que la ruta existe y tiene el middleware correcto:
   ```php
   Route::post('documentos/subir', [DocumentoSolicitudController::class, 'store'])
       ->name('portal.documentos.subir')
       ->middleware(['auth', 'ciudadano']);
   ```

7. En `php.ini` (o en `.htaccess` / `nginx.conf`):
   ```
   upload_max_filesize = 10M
   post_max_size = 12M
   ```

## CRÍTICO 2 — PDFs del ZIP salen corruptos
═══════════════════════════════════════════════════════════════════

El ZIP descarga correctamente pero los PDFs dentro (excepto el primero) no se pueden abrir.

Corregir en `app/Services/FormatosService.php`:

1. El problema es que DomPDF comparte el mismo buffer entre generaciones. Asegurarse de
   instanciar DomPDF separado para cada PDF:
   ```php
   foreach ($formatos as $nombre => $vista) {
       $pdf = Pdf::loadView($vista, $datos);
       $pdf->setOption('defaultFont', 'DejaVu Sans');
       $contenido = $pdf->output(); // NO usar stream() ni download()
       $zip->addFromString($nombre . '.pdf', $contenido);
       unset($pdf); // liberar memoria
   }
   ```

2. Asegurarse de que `ob_get_clean()` o `ob_clean()` NO se llame entre generaciones si
   se usa output buffering compartido.

3. El ZipArchive debe cerrarse DESPUÉS de agregar todos los archivos:
   ```php
   $zip = new ZipArchive();
   $zip->open($rutaZip, ZipArchive::CREATE | ZipArchive::OVERWRITE);
   // ... agregar todos los archivos ...
   $zip->close(); // solo al final, una sola vez
   ```

4. Probar individualmente en tinker:
   ```php
   php artisan tinker
   >>> $s = App\Models\SolicitudCredito::find(1);
   >>> App\Services\FormatosService::generarZip($s);
   ```

## CRÍTICO 3 — Error 500 en recuperación de contraseña + throttle sin mensaje
═══════════════════════════════════════════════════════════════════

Al hacer clic en "Enviar enlace de recuperación", el servidor devuelve HTTP 500.
El segundo intento dice "Por favor espera" sin indicar cuánto tiempo.

1. Configurar el mailer en `.env`:
   ```
   MAIL_MAILER=smtp
   MAIL_HOST=smtp.mailtrap.io   # O el servidor real
   MAIL_PORT=2525
   MAIL_USERNAME=tu_usuario
   MAIL_PASSWORD=tu_password
   MAIL_FROM_ADDRESS=no-reply@iyemyucatan.com
   MAIL_FROM_NAME="IYEM — Programa CREA"
   ```
   Para pruebas locales usar `MAIL_MAILER=log` — el link llegará a `storage/logs/laravel.log`.

2. En `app/Http/Controllers/Auth/PasswordResetLinkController.php` envolver en try/catch:
   ```php
   try {
       $status = Password::sendResetLink($request->only('email'));
   } catch (\Exception $e) {
       Log::error('Password reset error: ' . $e->getMessage());
       return back()->withErrors(['email' => 'No se pudo enviar el correo. Intenta de nuevo.']);
   }
   ```

3. Mejorar el mensaje del throttle en `resources/lang/es/passwords.php`:
   ```php
   'throttled' => 'Por favor espera 60 segundos antes de solicitar otro enlace.',
   ```
   Si no existe el archivo de idioma: `php artisan lang:publish` y luego editar el archivo es.

4. Verificar que la tabla `password_reset_tokens` existe: `php artisan migrate:status`.

## CRÍTICO 5 — Sin validación de rango de monto por modalidad
═══════════════════════════════════════════════════════════════════

Un Artesanal puede poner $1 o $1,000,000. No hay validación del rango oficial:
- Artesanal: $5,000 – $25,000
- Emprendedores: $25,000 – $150,000
- Sustentable: $25,000 – $500,000

   ```php
       'monto_solicitado.min' => "El monto mínimo para {$modalidad->nombre} es " . number_format($modalidad->monto_minimo, 0, '.', ',') . " MXN.",
       'monto_solicitado.max' => "El monto máximo para {$modalidad->nombre} es " . number_format($modalidad->monto_maximo, 0, '.', ',') . " MXN.",
   ]);
   ```

2. En el Vue (WizardCredito.vue, paso 5), mostrar el rango bajo el campo:
   ```vue
   <p class="text-xs text-slate-500 mt-1">
     Rango permitido: {{ fmt(modalidadSeleccionada.monto_minimo) }} –
     {{ fmt(modalidadSeleccionada.monto_maximo) }}
   ```

## ALTA 1 — "¿Olvidaste tu contraseña?" lleva al dashboard si hay sesión activa
═══════════════════════════════════════════════════════════════════

Cuando el usuario ya está logueado y navega hacia atrás hasta el login, el botón
"¿Olvidaste tu contraseña?" redirige al dashboard en lugar de la pantalla de recuperación.

En `routes/web.php`, verificar que las rutas de auth tienen el middleware `guest`:
```php
Route::middleware('guest')->group(function () {
    Route::get('password/reset', [PasswordResetLinkController::class, 'create'])
        ->name('password.request');
    // ... otras rutas de auth
});
```
El middleware `guest` redirige a `/dashboard` si hay sesión, pero el problema es que el botón
en la página de login lleva a `password.request` y el middleware `guest` detecta la sesión y
redirige. La solución es: si el usuario está autenticado y llega a estas páginas, redirigir
explícitamente al dashboard con un mensaje claro, NO al formulario de recuperación.

## ALTA 2 — Campos obligatorios no muestran error al estar vacíos
═══════════════════════════════════════════════════════════════════

Al avanzar pasos con campos vacíos, no hay feedback visual en el campo específico.

En `resources/js/Pages/portal/WizardCredito.vue`, crear un sistema de validación por paso:

```typescript
// En el composable o dentro del componente:
const errores = ref<Record<string, string>>({});

function validarPaso(paso: number): boolean {
  errores.value = {};
  const camposRequeridos = getCamposPorPaso(paso);

  for (const campo of camposRequeridos) {
    const valor = getNestedValue(form, campo.key);
    if (!valor || String(valor).trim() === '') {
      errores.value[campo.key] = campo.label + ' es obligatorio';
    }
  }

  if (Object.keys(errores.value).length > 0) {
    // Scroll al primer error
    const primerError = document.querySelector('[data-error]');
    primerError?.scrollIntoView({ behavior: 'smooth', block: 'center' });
    return false;
  }
  return true;
}

function siguiente() {
  if (!validarPaso(pasoActual.value)) return;
  // continuar...
}
```

En cada input del wizard agregar:
```vue
<input ... :class="errores['campo'] ? 'border-red-500' : 'border-slate-300'" />
<p v-if="errores['campo']" class="text-red-500 text-xs mt-1">{{ errores['campo'] }}</p>
```
